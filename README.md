# New Komitas — exterior 3D (photoreal)

Procedural Blender model of the New Komitas residential complex (Metta Group, Arabkir, Yerevan):
two mirrored 18-storey courtyard blocks, reconstructed from the developer's official renders,
the developer's 3D site video and the newkomitas.am facts. Everything is generated by scripts,
so any dimension or facade decision can be changed and rebuilt in seconds.

## Repository and deployment

This folder is a Git repository. `Website/` is the complete static site (no build step), and
`.github/workflows/deploy-pages.yml` publishes it to GitHub Pages on every push to `main` that changes it:
`https://<github-user>.github.io/<repo>/`.

| In Git | Not in Git (regenerate with the scripts) |
|---|---|
| `Scripts/`, `Web-Build/*.sh`, `Website/` (site + built assets, ~98 MB), `Reference/osm_*`, `Renders/v7-final/*.jpg`, launchers, README | `Blender/` (452 MB, from `nk_build.py`), `Web-Build/` outputs (976 MB: float lightmaps, logs, artifact staging), older renders, the developer photos in `Reference/`, `Website-original/` |

Update the live site: rebuild, then `git add -A && git commit -m "..." && git push`; the Pages workflow redeploys in
1-2 minutes. When assets change, bump `RELEASE` in `Website/app.js` and the `?v=` keys in `index.html`, `app.js` and
`traffic.js` (Pages caches files for 10 minutes; the keys make browsers fetch the new ones).
Limits: 100 MB per file (largest now 37.9 MB), 1 GB per site, about 100 GB of traffic a month (a desktop visit
downloads ~50 MB, a phone visit ~20 MB). A Pages site is public even when the repository is private. Any static host
can serve `Website/` instead, except Cloudflare Pages (25 MB per-file cap). Map data (c) OpenStreetMap contributors
(ODbL); the two developer renders in the site's "View reference" tabs are credited reference images.

## Rebuild / render

```bash
cd ~/Desktop/Homelia/new-komitas-project-3D
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup -P Scripts/nk_build.py
/Applications/Blender.app/Contents/MacOS/Blender -b Blender/NewKomitas-Exterior.blend -P Scripts/nk_render.py -- --cams CAM_Street,CAM_Aerial,CAM_Park,CAM_Front --scale 1.0 --samples 192 --tag final
```

Build ≈ 6 s, preview render (40 %, 48 spp) ≈ 10–20 s, final 2K (192 spp) ≈ 5–8 min per view on the M1 Max.

| Script | What it does |
|---|---|
| `Scripts/nk_build.py` | Footprint, facade scores per wall run, roof, sky/sun, cameras, compositor; saves `Blender/NewKomitas-Exterior.blend` |
| `Scripts/nk_facade.py` | Facade grammar: balcony columns (angled trays), 1.6 m glass strips, copper frames, picture frames, bronze bands, windows, parapets |
| `Scripts/nk_mats.py` | PBR materials (procedural, UV0 in metres so tiling textures can replace them in Unreal / three.js) |
| `Scripts/nk_site.py` | Streets, raised pavements with curbs, courtyards (courts, playground, lawns), tree layout, foreground grass |
| `Scripts/nk_trees.py` | Procedural species (plane, linden, maple, poplar, birch, shrub) as instanced collections |
| `Scripts/nk_citygen.py` | Real neighbours from OSM footprints as Yerevan typologies: Soviet tuff blocks, panel blocks, towers, houses, sheds, garages, shops — window reveals/frames/sills, balconies (open, enclosed, glass), AC units, entrances, cornices, metal/tile/flat roofs, weathering |
| `Scripts/nk_context.py` | Older generic context (used only with `--generic`) |
| `Scripts/nk_props.py` | Procedural parked cars (read well only small in frame) and street lamps |
| `Scripts/nk_render.py` | Renders cameras; sets the sun (`when`) and cloud amount (`clouds`) per camera |
| `Scripts/compare.sh` | Side-by-side official render vs model render |

## Conventions

* World frame: metres, Z up, X = east, Y = north, origin between the blocks. Block A (west,
  Phase 1) spans x −122…−11, block B x 11…122, y −48…55.
* The current website's Blender frame is this frame rotated +90° (site x = −north, site y = east).
* Sun: Nishita sky with the true solar position for Yerevan; `sun_rotation` = compass azimuth
  (verified with a top-down shadow render). Exposure −3 EV, AgX Medium High Contrast.
* Context buildings, trees and roads are generic/schematic (artist's impression), not surveyed.

## Localhost 3D site (photoreal, baked lighting)

Double-click **`Start 3D Site.command`** → http://localhost:8770 (or `python3 Scripts/serve.py`).
The first time, macOS may ask to let Terminal access the Desktop folder — allow it. Stop with Ctrl+C.

**On a phone or tablet:** double-click **`Start 3D Site (Phone).command`** instead (`serve.py --lan`). The
Terminal prints `http://<this Mac's Wi-Fi address>:8770/` and a QR code: scan it with the phone's camera
(same Wi-Fi). If macOS asks whether Python may accept incoming connections, choose Allow. On iPhone,
Share → *Add to Home Screen* opens it full-screen like an app. The plain launcher stays Mac-only.

What phones get (decided per device, not by window width: touch screens, small screens and ≤ 4 GB
devices; `?mobile` / `?desktop` force either):

| | Desktop | Phone / tablet |
|---|---|---|
| Model | opens with `new-komitas-complex-mobile-ktx2.glb` (12 MB), then streams `assets/lm/` (27 MB: blocks as 4096² JPEG, neighbours 4096² and ground 2048² KTX2); texture GPU memory ~410 MB instead of ~780 MB; `new-komitas-complex.glb` (42 MB) is the fallback | `new-komitas-complex-mobile-ktx2.glb` (12 MB, 2048² KTX2/ETC1S; GPU memory for textures ~25 MB instead of ~195 MB; JPEG `-mobile.glb` is the fallback) |
| Reflections | `komitas-env.hdr` (2048) | `komitas-env-1k.hdr` |
| Trees | `tree/<Species>.webp` (256 px views) | `tree/<Species>-mobile.webp` (128 px views) |
| Cars | clearcoat paint | same models, standard paint (cheaper) |
| Frame budget | vsync | 60 fps while the camera moves, ~25 fps for traffic/breeze alone; resolution drops automatically if the GPU falls behind |

**Using it:** drag to rotate; right-drag (desktop) or two fingers (touch) to move around the neighbourhood;
scroll, pinch, or double-click / double-tap to zoom towards a point. Every apartment has its own link
(`…/#A-1204`): the **Share** button in its panel sends or copies it, opening it flies straight to that
apartment, and the browser's Back button closes it again. Taps on phones have a finger-sized tolerance.

**Measuring a real phone:** open `http://<Mac address>:8770/?bench` on it (the Phone launcher prints the
exact link). The camera circles the complex for 16 s; the phone shows its frame rate and the result is
saved on the Mac in `Web-Build/device-reports/<time>-<device>.json` (also printed in the Terminal).

**Desktop loading:** the page opens with the 12 MB phone model, then streams full-resolution lightmaps
from `assets/lm/` (most looked-at first; a small "Sharpening textures" note shows progress): the two blocks
as their original 4096 px JPEGs (ETC1S tints large flat walls slightly at that size), the neighbours and
ground as KTX2. The loading screen shows a photoreal still while this happens.

Layout: portrait phones get a slim header and a bottom sheet for the list/filters that folds to one line
(the camera re-frames to the taller view); landscape phones a compact side panel; 44 px touch targets,
16 px selects (no iOS zoom), safe areas for the notch/home bar; the detail panel shifts the 3D view so the
chosen apartment stays visible beside/above it. The server gzips JSON/JS (apartments 729 → 38 KB) and
answers unchanged files with 304, so a reload on the phone does not re-download 12 MB.

Rebuild order:

```bash

NK_DETAIL=web $B -b --factory-startup -P Scripts/nk_build.py -- --web --out "$PWD/Blender/NewKomitas-Web.blend"
```

QA: `?qa` adds a diagnostics panel and `window.komitasQA` (`traffic()`, `tier()`, `advance(seconds)` to step
frames while a preview pane is hidden, `internals()`); it also keeps the WebGL drawing buffer for screenshots.

Realism pass (site v0.10, judged against the developer's renders): vegetation about 2.6x denser
(12,448 trees: street trees every 6.5-9.5 m, denser parks/lawns/yards with more mature trees, shrubs
along the walls of the nearer buildings, hedges along the mapped fences); new ground materials (muted
lawns with sun-dried patches and worn earth, dusty unirrigated land with soil and gravel, worn mid-grey
asphalt with repairs instead of near-black); flat roofs as bitumen/coated membranes in per-building tones
with roll seams, plus water tanks, AC units, vent stacks and dishes; the look is AgX Punchy, -2.8 EV,
6700 K white balance and a small toe lift (warmer, shadows sky-lit grey instead of crushed black) for the
stills, the lightmaps, the sky and the tree views alike.

Black artefacts while moving (fixed): (1) texels that never see light (ground under every building,
faces hidden inside the model: 15-25% of some atlases) were baked pure black and bled into visible
surfaces at lower mip levels; `nk_web.bake_target` now refills them from their surroundings (push-pull)
before denoising; (2) the page resized the canvas after drawing when a phone adapted its resolution,
which showed one black frame; resizing now redraws immediately; (3) shade itself displayed near black: deep shade (street canyons, ground under the trees, radiance ~0.01)
came out at ~13/255 through AgX Punchy. Lightmaps and tree views now pass through `nk_web.shadow_fill`, a sky-fill
term that fades out with brightness (L -> L + 0.09 * exp(-L / 0.3), applied as a gain so colours keep their
ratios): deep shade ~38/255, ordinary shade 86 instead of 79, sunlit surfaces unchanged (measured through the
view transform). `nk_web.py -- regrade` re-applies grade + fill from the saved float lightmaps
(`Web-Build/lightmaps-float/*.npy`) without re-baking. (The stills get the same lift from their haze pass.) Trees are billboarded in the vertex
shader (static instance data), so 12k trees cost nothing per camera move.

Walls and fences: the OSM `barrier=wall / fence / retaining_wall` ways (about 3.9 km after clipping) are built
by `nk_citygen.barriers()`: tuff or plaster walls 2.1 m high (or the tagged height) with a concrete coping,
fences as a plinth with steel posts and rails, retaining walls in concrete; clipped out of carriageways,
building footprints and our site.
